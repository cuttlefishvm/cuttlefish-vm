Inference served by a local Ollama instance.

Ollama is the first real backend because it is the shortest path to a real model: it is already an HTTP server that streams, so this is a client rather than an embedding of llama.cpp. Embedding llama.cpp directly remains worthwhile later — it removes a process boundary and gives direct control of the KV cache — but it is a much larger commitment, and nothing above InferBackend can tell the difference.

§The wire format

POST /api/generate with stream: true responds with newline-delimited JSON — one object per token, then a final object carrying counts:

{"model":"llama3.2:1b","response":"Hello","done":false}
{"model":"llama3.2:1b","response":" there","done":false}
{"model":"llama3.2:1b","response":"","done":true,"done_reason":"stop",
 "prompt_eval_count":28,"eval_count":3, ...}

Token-at-a-time delivery is what makes a guest’s early-stop verdict meaningful: the host can act on it while generation is still running rather than after the fact.

§Pinned generation

Plain targets such as Ollama "qwen3.8:27b" keep the original behaviour. A JSON target opts into a required digest pin and explicit generation controls:

model = Ollama "{\"model\":\"qwen3.8:27b\",\"expected_digest\":\"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa\",\"seed\":42,\"temperature\":0.2,\"format\":\"json\",\"think\":false}";

Replace the example digest with the actual 64-digit digest from GET /api/tags. Each configured generation checks that mapping before and after inference and checks the response model. Usage records the requested tag@sha256:digest; successful inference means those checks passed. This is tag-mapping evidence, not atomic attestation of the weights served. Resuming stored results does not re-attest their identity. Keep the server and model files stable during a campaign.

Supported generate controls are integer seed, nonnegative finite temperature, format ("json" or a JSON Schema object), and boolean think. Omitted controls retain Ollama defaults; num_predict always comes from the request budget. Unknown fields fail. Thinking and schema support remain model/server dependent; server errors propagate. A seed does not guarantee identical output across versions or hardware. Schema output still needs independent acceptance validation.
