1//! Native tooling for AI agents: a local runtime for jobs an agent hands off.
2//!
3//! A coding agent delegates a job — summarize this, classify that, extract
4//! these fields — and Cuttlefish runs it on this machine against a local
5//! model, returning a structured result. Two things make that worth doing:
6//!
7//! - **Data stays local.** For jobs marked local-only, the calling agent
8//!   passes *paths*, not contents. Cuttlefish opens the files itself, so
9//!   proprietary source and personal data never enter a frontier model's
10//!   context at all. The guarantee is not "we also ran something locally" — it
11//!   is that the remote model never received the bytes.
12//! - **Frontier prices stop applying to grunt work.** Bulk, repetitive, and
13//!   mechanical subtasks do not need a trillion-parameter model, and offloading
14//!   them keeps tokens and context for the work that does.
15//!
16//! The limitation is worth stating plainly rather than discovering later: you
17//! cannot run a frontier-class model on a laptop. Cuttlefish targets the large
18//! subset of agent work that does not need frontier reasoning. It is not a
19//! replacement for one.
20//!
21//! # How a job runs
22//!
23//! A job is described by a `.cuttlefish` spec — which model, what the job may
24//! touch, and which processing block implements it. The block is compiled to
25//! WebAssembly and runs sandboxed inside the daemon, which serves inference
26//! from a local model and streams results back to the caller.
27//!
28//! Three decisions shape the rest of the system, and each exists to avoid a
29//! specific failure rather than to express a preference:
30//!
31//! **The host drives the guest.** A block is a state machine: it returns
32//! *commands* (`Infer`, `Open`, `Slice`, `Done`) and the host executes them,
33//! then steps the block again. The obvious alternative — let the guest call
34//! into the host and block until it answers — cannot work, because a
35//! single-threaded wasm guest offers no execution context for the host to call
36//! back into, and inference must run on a different thread from the (`!Sync`)
37//! wasm store. Inverting control also makes cancellation trivial: the host
38//! simply stops stepping, so no guest cooperation is required.
39//!
40//! **Bulk data never enters guest memory.** A block receives a handle and a
41//! length, then pulls bounded windows. Guest memory tracks the window size, not
42//! the input size, so a block written against a README behaves identically
43//! against a corpus — and the 4 GiB ceiling of 32-bit wasm binds on nothing we
44//! actually do.
45//!
46//! **Capabilities are deny-by-default and checked twice.** A block reaches
47//! nothing unless its spec grants it. The grant is verified when the spec is
48//! compiled and again by the sandbox at runtime. The compile-time check is a
49//! convenience that produces good error messages; the runtime check is the
50//! security boundary.
51//!
52//! # This crate
53//!
54//! This is the facade. It ships the `cuttlefish` command-line client and
55//! re-exports the workspace's pieces, so that one page documents the whole
56//! system. The implementation lives in sibling crates:
57//!
58//! - [`abi`] — the contract between host and guest.
59//! - [`core`] — parsing `Cuttlefish.spec` files.
60//!
61//! # Project conventions
62//!
63//! Documentation lives in the code rather than in a separate design document,
64//! so that explanations sit beside what they explain and go stale loudly
65//! instead of quietly. Comments state *why* code looks the way it does, never
66//! what it does. See `AGENTS.md` in the repository for the full contract.
67//!
68//! [cuttlefish]: https://cuttlefishvm.github.io/
