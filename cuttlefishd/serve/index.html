Serving the API over a machine-local, OS-permission-gated transport: a unix domain socket on unix, a named pipe on Windows.

Both are deliberate choices over a TCP listener. The daemon’s access control is the endpoint’s own permissions — it executes wasm and drives local models, so “any process on this machine may connect” is a materially weaker posture than “whoever can open this socket file may connect”. A loopback TCP port has no such gate and would need an auth token bolted on just to get back to where we already are. Named pipes are the Windows analogue of the unix socket, not a workaround for the lack of one.
